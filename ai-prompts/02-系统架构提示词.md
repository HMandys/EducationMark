# 系统架构提示词

请你以资深系统架构师身份，为“EduMark 智能阅卷与家长查分平台”设计完整系统架构。

技术栈固定如下：
- 后端：Java 17 + Spring Boot 3 + Spring Security + JWT + MyBatis Plus + MySQL + Redis + MinIO
- 管理端：Vue3 + TS + Vite + Element Plus
- 家长/学生端：UniApp
- AI 模块：独立 AI Service，支持接入多种大模型

请输出：

## 1. 总体架构图（文字版）
要求分层说明：
- 客户端层
- 网关层（如果有）
- 应用服务层
- 业务层
- 数据层
- 对象存储层
- AI 服务层

## 2. 系统模块划分
请拆分为：
- 用户权限服务
- 学校组织服务
- 考试管理服务
- 阅卷服务
- 成绩服务
- 查询服务
- AI 分析服务
- 文件服务
- 报表服务
- 审计日志服务

## 3. 单体还是微服务
请分析为什么当前阶段更适合：
- 模块化单体
或
- 微服务

并给出建议方案。

## 4. 数据流设计
请描述以下数据流：
- 学校导入学生名单 -> 入库
- 上传答题卡 -> MinIO -> 图像地址入库
- 阅卷提交 -> 阅卷记录 -> 成绩汇总
- 成绩发布 -> 家长端查询
- AI 分析 -> 报告落库 -> 页面展示

## 5. 权限架构
请设计 RBAC 权限模型：
- 用户
- 角色
- 权限
- 数据范围
- 菜单权限
- 接口权限
- 学校隔离

## 6. 核心表关系
请先概述核心实体与关系，不用 SQL，输出 ER 思路：
- 学校
- 年级
- 班级
- 学生
- 家长
- 教师
- 考试
- 科目
- 试卷
- 题目
- 答题卡
- 阅卷任务
- 阅卷记录
- 成绩
- 知识点
- AI 报告

## 7. 高可用与性能
请说明：
- Redis 用在哪
- MinIO 用在哪
- 如何避免重复阅卷
- 如何支持高并发查分
- 如何做分页与索引优化
- 如何做成绩统计优化

## 8. 安全设计
请说明：
- JWT 鉴权
- 密码加密
- 防越权
- 防止家长看到其他学生成绩
- 文件访问权限
- 操作日志审计
- 敏感数据脱敏

## 9. 可扩展设计
请说明未来如何扩展：
- 多学校 SaaS 化
- OCR 接入
- 机器阅卷
- 智能出卷
- 错题本训练
- 微信消息通知

输出必须专业、可落地、不是泛泛而谈。
